# Referee round 6 — the two reports DISAGREE on the central design question

Both referees agree on one thing: **the 512-control rank must come out of
candidate generation.** They prescribe different replacements.

| | Referee 1 | Referee 2 |
|---|---|---|
| Replacement screen | **Adopt the beam-separated ensemble** as the primary screen | **No screen at all** — every threshold crossing goes straight to the visibility fit |
| Windows to vet | the **28** separated-screen windows | all **56** crossings |
| Separated ensemble | primary candidate generator | "Do not adopt as the new screen either"; keep as a released descriptive column |
| P90^sel | re-measure for the separated screen | re-measure through **trigger + visibility fit** |

## Resolution I propose

**Referee 2's design satisfies Referee 1's scientific requirement, and R1's
does not satisfy R2's.** The 28 separated-screen windows are a subset of the
56 crossings, so testing all 56 vets all 28 *a fortiori*. R1's stated goal —
"even when the screen is reconstructed using only spatially independent
controls, none survives localisation" — is reached, and strengthened, by
"every window that triggered was localisation-tested, and none survives".

Referee 2's objection to adopting the separated ensemble is also the stronger
argument on the merits: on ACA, 64 % of the survey, a rank floor of 1/14
means a valid screen is barely a screen. Adopting it as *primary* would make
the candidate list depend on the arbitrary construction of the ensemble,
which is precisely R1's own complaint about the 512.

**Recommendation: take Referee 2's path — remove the rank from candidate
generation, run the drift-following visibility fit on every crossing — and
say so explicitly in the response letter to Referee 1**, noting that it
delivers what they asked for and more.

**This is Glenn's call to confirm, not mine to assume.**
